### gpio模式（8051）

1. 准双向口 ：弱上拉，既可以输入又可以输出，灌电流可达20ma，拉点六为270~150ua
2. 推挽输出 ：强上拉，可达20ma，要加限流电阻
3. 高阻输入 ：电流既不能流入也不能流出，但可以用于测电平
4. 开漏输出 ： 内部上拉电阻断开，开漏模式既可以读外部状态也可以对外输出（高电平或低电平）。如要正确读外部状态或需要对外输出高电平，外加上拉电阻，否则读不到外部状态，也对外不输出高电平。

- 注意32部分使用的是输入，输出，复用，模拟

### 定时器

组成：计数器和时钟源组成，

作用：产生一定时间间隔的中断信号

工作模式（计数方式）：

- **16位自动重载模式**：定时计数两种 模式，每当定时器溢出时就会触发中断或输出信号
- 16位不可重载模式：计数值达到设定值后，定时器就会停止计数，需要重新初始化才能继续计数
- 8位自动重载模式
- 不可屏蔽中断的16位自动重载模式：16位计数器溢出时触发中断或输出信号，并可以通过软件或硬件方式清除定时器的值

中断配置：为了打开中断开关，从而可以触发终端回调的，如果不配置，将无法触发中断回调。

时钟源：可配置的是：1T 跟随主频；12T进行12分频

是否输出高速脉冲：端口同步输出时钟脉冲

时钟周期设置：1m执行多少次timer中断；时钟周期=1/时钟源频率

```
TIM_InitStructure.TIM_Value     = 65536UL - (MAIN_Fosc / 10000UL);
```

注意时钟周期的取值范围，通过以上数学公式，（MAIN_Fosc / Timer频率）不能大于65536UL也就是2us调用一次，回调函数中执行的代码时长就不能超过这个值，

24M主频，一个时钟周期为1/24MHz = 41.67ns，

### PWM(脉宽调制)

PWM输出的频率和占空比可以由程序控制，用于电机、灯光和其他设备的亮度速度等参数，代码中PWM周期是指N等份切分一秒钟

```
PWM_Period = MAIN_Fosc / 8 = 24M / 8 = 3M =3000000单位每次，即3M作为Period参数，可以得到PWM方波每个周期的时长为 1 / 8 = 0.125s
```

代码中的配置：

```
#define PERIOD (MAIN_Fosc / FREQ) //周期
PWMx_InitStructure.PWM_Period = PERIOD - 1;//计数器从零开始计数
```

### 电位器（ADC）

![image-20260615203541987](./复习.assets/image-20260615203541987.png)

1. 通过万用表测量 `P0.5`位置的电压

ADC概念：

- 采样：是指在一定时间间隔内对模拟信号进行测量，并将测量值存储在数字形式的数据中

- 量化：将连续的模拟信号值离散化为一系列数字值，通常使用二进制表示

初始化流程

1. io口初始化为高阻输入

2. 结构体初始化，

   1. 模拟信号采样时间控制，0~31（不能设置小于十），通道选择时间控制0（默认），1；
   2. 通道选择保持时间控制0，1（默认），2，3；
   3. 设置ADC工作时钟频率 ADC_SPEED_2X1T~ADC_SPEED_2X16T;
   4. ADC结果调整（对齐方式）ADC_LEFT_JUSTIFIED,ADC_RIGHT_JUSTIFIED；
   5. 结构体初始化
   6. ADC电源开关
   7. 中断使能

3. 数据读取与转化

   1. ```
      result = Get_ADCResult(ADC_CH13);
      v = result * 2.5 / 4096;
      ```

###### 	mtu是什么

数据链路层中能承载的最大数据包大小，设备和协议分的，如果超出某个设备或链路的MTU限制，就会发生分片，导致额外的处理开销和延迟

###### 蓝牙的五种状态，就绪，广播，扫描，发起，连接

初始化：ble启动进行初始化，打开蓝牙，设置设备的名称，广播参数等

广播：初始化后，BLE设备开始进行广播，向周围的设备发送广播包，广播数据包中包含设备的标识符，服务UUID等信息，用于让其他设备能够发现和连接到该设备

扫描：其他BLE设备在扫描状态下可以监听并接受周围设备发送的广播数据包，当扫描到感兴趣的设备，可以进一步与设备进行连接

连接请求和响应：当一个设备想要与广播设备建立连接时，发送一个连接请求给广播设备，广播设备收到连接请求后可以选择接收或者拒绝，接受后广播设备会发连接响应给请求设备

建立连接：一旦连接请求和响应成功完成，BLE设备之间建立连接，在连接状态下，设备之间可以进行数据交互，通信和控制

BLE连接过程属于主从架构，一个设备从当主设备，负责发送连接请求和控制连接过程；另一个设备充当从设备的角色，负责接收连接请求和提供服务。
